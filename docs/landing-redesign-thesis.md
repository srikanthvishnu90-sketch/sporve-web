# Landing redesign spec — thesis (2026-08-13)

Owner framing: *"redesign the layout, colors information and others shouldn't be
deleted on the landing page just information rearranged."* Mode: thesis. No code
written.

## THESIS

About a third of this spec is buildable in this stack, and the third that is
buildable is mostly already built. The spec is written against a
React/Vite/Next-style app with a build-time image pipeline and a component
library; this repo is one 2.0MB `index.html` generated by `python3 src/build.py`,
with every font and hero photo base64-inlined and a `default-src 'self'` CSP that
allows images only from `'self' data:`. The image third of the spec (WebP/AVIF,
`srcset`/`sizes`, blur-up, `preload`+`fetchpriority`, Vercel image optimization,
vite-imagetools, ≤80KB cards) is not merely hard here — `preload` and
`fetchpriority` on a `data:` URI are definitionally no-ops, because the bytes
already arrived inside the document. The colour third asks for `#F8FAFC`, a value
this repo *retired on purpose* (`src/sporve-web.host.html:2740`) and for `#334155`
and `#E2E8F0`, neither of which is a `:root` token — that is a palette change,
which CLAUDE.md §3 freezes. The layout third — hero shortened, search bar at the
seam, a peeking card row, one card geometry, snap rails — is real, mostly
achievable, and partly already shipped. Honest scope: a layout-and-rhythm pass on
`landingHTML()` with zero new hex, zero new assets, and no perf promise.

## PREMISE ERRORS (evidence)

1. **"Hero is 100vh."** False. `.band.hero{padding:86px 0 78px}`
   (`sporve-web.host.html:1538`); the landing hero has no `vh` height at all — it
   is intrinsic. The only `100vh` is `min-height` on `#app` (`:168`), the app
   shell, so the *ground* reaches the fold on short routes. Cutting it to 70vh
   would not shorten the hero; it would let short pages end mid-viewport.
   Separately, `LANDING-SPEC.md:136` already adjudicated **55vh**, and it was
   never applied. The spec reverses a settled number without knowing it exists.
2. **`#F8FAFC` / `#E2E8F0` / `#334155`.** `#F8FAFC` appears once as prose at
   `:2740`: *"`#F1F5F9` was ~invisible… `#F8FAFC` retired."* It was tried and
   rejected as too weak against white. `#E2E8F0` exists only inside the avatar
   placeholder SVG (`:3378`). `#334155` does not exist. The live tokens are
   `--raise:#F7F8FA`, `--raise2:#EFF2F5`, `--rule:#E3E7EC`, `--slate:#223140`
   (`:12–24`), and the band slate is `#E9EEF4` with a `#CBD5E1` rule (`:854`).
   Under CLAUDE.md §3 these are frozen. Reject.
3. **Images.** `src/build.py:203–219` base64-inlines every `assets/hero-*` into
   the HTML. Current heroes: `hero-1-swimming.jpg` 194KB, `hero-2-tennis.jpg`
   121KB, expanded ~33% by base64 to 442KB of the built file. The build's MIME map
   already accepts `webp` — so *re-encoding the two source files to WebP is the
   one image item that ships today*, and it is the only one. `srcset`/`sizes`
   cannot work: one inlined URI per photo, no variants. Vercel image optimization
   needs `/_vercel/image` plus an `images` block in `vercel.json` and external
   fetches the CSP forbids; vite-imagetools needs Vite, which does not exist here
   (no npm build). Card images are not photos at all — they are generated inline
   SVGs (`phShot()`/`phAvatar()`, `:3370–3382`), so "card ≤80KB" is already
   satisfied at ~0.4KB and the whole srcset apparatus has nothing to act on.
4. **"ONE CoachCard reused everywhere."** There are at least six geometries:
   `.card` 16:10 shot, 14px padding, `--r-xl` (`:965`); `.card.feature` 16:9,
   span-2 (`:983`); `.kcard` fixed 172px image, `--r-l`, 1px `--rule` border
   (`:1154`); `.pickcard` (`:1505`); `.aidock-pick` (`:1341`); `.lcard` (`:2586`).
   Collapsing them to one 4:3 / 12px / `#E2E8F0` card is a cross-route refactor of
   five other surfaces, not a landing change — and it is out of scope under
   CLAUDE.md §2.
5. **Horizontal snap rows.** Already shipped: `.rail-track` (`:915`, `scroll-snap-type:x proximity`, `flex:0 0 228px`) and `.kindrow` (`:956`, `x mandatory`),
   both with hidden scrollbars, a pager at `:9408`, and `80vw` basis on mobile
   (`:922`, `:963`). The spec's 280/240px width contradicts the tuned 228/80vw.
6. **"The peek" / first card row.** `landingHTML()` (`:4973–5175`) contains **no
   card row at all** — its sections are hero + ticker, sport tile grid, dark
   "Every listing here is a real one", "Two ways in", "See the real screens",
   "What you get, either way", "Three steps", trustband, final CTA. Making a card
   row peek above the fold means *adding* a card row, i.e. new information, which
   the owner's framing forbids. What can peek instead is the existing sport grid.
7. **Section rhythm.** Current ladder: hero → white → **dark** → alt → white →
   alt → alt → black trustband → finalcta. That is CLAUDE.md §5 chapters, with a
   deliberate `alt`+`alt` run. Mechanical `#FFFFFF`/`#F8FAFC` alternation
   contradicts §5 twice: it removes the black chapters that carry the trust story,
   and it flattens the doubled run. Reject.
8. **Lighthouse mobile ≥90 / CLS <0.02.** Not plausible unchanged. The document
   gzips to **919KB** and is a single render-blocking HTML file: ~1.32MB of inline
   CSS/JS parsed on the main thread before first paint, plus 442KB of
   non-compressible base64 image payload inside that same document. LCP is the
   hero photo, which cannot start loading before the document finishes
   transferring — that is the architecture, not a tuning problem. CLS <0.02 is
   already close: `.hero-panel` carries `aspect-ratio:1000/612` (`:514`) and
   `.card .shot` `aspect-ratio:16/10`, so boxes are reserved. Promise CLS, not
   Performance.

## CONFLICTS WITH CLAUDE.md / SUBPAGES

- §3 colour law — three non-token hex values, one explicitly retired. Blocking.
- §5 rhythm — mechanical two-tone alternation replaces chapters. Blocking.
- §2 change only what was asked — one-card-component touches five other routes.
- §9 check premises — items 1, 2, 3 are load-bearing and false.
- `LANDING-SPEC.md:133,136,242` — "delete the dark hero panel, 55vh, canvas is

  (70vh) and silently duplicates (white body below hero). Surface, do not pick.

## RECOMMENDED CUT

**Build now (GREEN, no palette change, `landingHTML()` + the `.hero` rules only):**

1. Shorten the hero to the already-adjudicated 55vh via `max-height` on
   `.hero-in`, not by touching `#app`'s `min-height`.
2. Let the sport-tile grid's header and top ~35% of the first tile row sit above
   1440×900 — the "peek", using content that already exists.
3. Move `searchPillHTML()` to straddle the hero/next-band seam (negative margin +
   `z-index`), keeping every `data-*` handler intact.
4. Re-encode the two hero JPEGs to WebP; `build.py` already supports the MIME.
   Expect ~30–40% off 315KB. One measurable win, zero architecture change.
5. Re-check rhythm after the move so no two white bands touch (§5).

**Defer:** unifying card geometries — worth doing, but as its own cross-route
task with `.card` as the survivor, not smuggled into a landing pass.

**Reject / send back:** all three hex values; mechanical `#FFFFFF`/`#F8FAFC`
alternation; `srcset`/`sizes`/AVIF variants/blur-up/`preload`/`fetchpriority`;
Vercel image optimization and vite-imagetools; Lighthouse Performance ≥90 as an
acceptance gate. Ask the owner one question: *does "redesign the colors" mean he
is reopening §3, or does he mean re-deploying the existing tokens differently?*
Everything colour-shaped in this spec hangs on that answer.

## FIVE-SENTENCE READING

The spec proposes replacing the landing's ground colours with three literals
(`#F8FAFC`, `#E2E8F0`, `#334155`) and adding a build-time responsive-image
pipeline. It cannot work as written because this page has no build-time image
step — `build.py` base64-inlines each photo as a `data:` URI, so there is exactly
one variant per image and `srcset` (the attribute that lets a browser choose among
several encodings by viewport width) has nothing to choose from. Downstream it
touches every route, since `.card`, `.kcard` and `.pickcard` are shared across
explore, search and the coach portal, and the band tokens are global custom
properties read by all sixteen product pages. It would break on the CSP
(`default-src 'self'`, `img-src 'self' data:`) the moment any external image host
is introduced, and on `smoke.sh`'s dark-ground invariant if `#334155` becomes a
band background carrying `--paper` text. Verified by reading the token block at
`sporve-web.host.html:12–24`, the retirement note at `:2740`, the inliner at
`build.py:203–219`, and by measuring the built page: 2,025,779 bytes raw,
919,317 gzipped, 442,220 of it base64 image payload.
